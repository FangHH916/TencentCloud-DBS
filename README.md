# DCTA 对话转账 Demo

独立的 DBS 赛题演示原型。无需密钥、npm 依赖或联网即可使用文字转账；不连接真实银行、不操作真实资金。

## 启动

需要 Node.js 22 或更新版本。Windows 双击 `start-demo.cmd`，或在本目录运行：

```powershell
node server.mjs
```

打开 http://127.0.0.1:8787 。服务仅监听本机地址。更改端口可设置 `PORT` 环境变量。

## 完整演示（约 5 分钟）

1. 单笔：输入“从储蓄账户给妈妈转 200 新元”。先指出余额不变；检查草稿，再点击“核对交易并授权”，勾选确认并执行。余额减少 200。
2. 歧义：输入“给 John 转 500”。可直接回复“John Tan，储蓄账户，SGD”，或在交易卡片中选择，重新校验再授权。
3. 多笔：输入“从储蓄账户给妈妈转 200 新元，再给 Alice 转 150 新元”。两笔作为同一个授权批次，先整体检查，再原子执行。
4. 高额：“从储蓄账户给妈妈转 2500 新元”。展示风控拦截；本版没有额外认证通道，因此不会继续执行。
5. 安全实验室：测试未经授权、签名后金额篡改、重复提交、提示注入、日志篡改。测试独立账户；重复提交案例第一笔合法成功、第二笔拒绝，总共只扣 200。
6. 审计记录：展开原始指令、澄清、校验、签名摘要、执行事件，验证哈希链，并导出 JSON。

初始储蓄余额 SGD 12,500，往来余额 SGD 3,200。单笔上限 SGD 2,000；一分钟最多五笔。每次最多三笔。已知收款人为妈妈、John Tan、John Lim、Alice。

## 调试与交互优化

- 支持中文小数（“二百点五” = 200.50）、全角数字及明确倍率（“1万” = 10,000，仍受额度限制）。模糊的“五百五”“一千二”会要求改写，不猜测金额。
- 英文收款人按单词边界匹配；“Alicefoo”不会自动匹配 Alice。多人“各转”表达要求拆成明确的多笔指令。
- 单笔草稿支持对话补充字段；多人批次通过卡片逐笔澄清，避免把一条回复分配给错误交易。
- 点击“取消草稿”或输入“取消”，原授权随即失效。无效的新输入保留已有草稿；有效新指令会替换并取消旧草稿。
- 可修改原指令重新生成；交易卡片展示进度与批次总额，确认窗口重复展示总额。
- 请求设有 12 秒超时；失败后刷新状态，避免在旧确认窗口继续授权。服务连接失败时提供“重新连接”。
- 补充信息、请求体校验失败返回可读的 400 错误，不会因 null 等输入触发 500 或部分修改草稿。

## 解析范围

离线模式是规则解析器，不是 LLM；支持明确金额的 SGD 转账、有限中文金额、有限中英文收款人和账户词汇。账户或币种未指定会要求补充，不默认猜测。相对金额、投资、其他币种、多个来源账户、复杂自然语言应拒绝或要求拆分。语音按钮使用浏览器识别引擎，可能需要联网和麦克风授权；识别后先展示文字，不自动执行。

## 架构

`public/` 网页 → `/api/interpret` 只读提案 → 只读规则语义验证与确定性风控 → 固定确认界面 → 模拟认证器 Ed25519 签名 → `/api/execute` 独立网关函数 → 模拟账本。

签名绑定会话、交易草稿摘要、唯一 nonce、有效期。摘要包含每笔交易的收款人、金额、币种、来源及草稿版本。执行时复核签名、摘要、状态、nonce、余额及频率；批次先整体预检再同步提交。对话解析模块无账本写入接口或签名密钥。

身份、认证器与账户都是模拟的，模块在同一 Node 进程内，不是生产隔离；`/api/authorize` 的模拟确认不能替代真实身份核验。日志和检查点也都在内存中，重启或重置后清空；哈希链只能在可信检查点假设下检测改动，不提供外部存证，也不防服务器管理员重写整条链。提示注入词表只覆盖有限测试，不是完整攻击防护。

## 接入真实模型

`lib/model-adapter.mjs` 提供未启用的提案接口契约。服务端适配具体模型后，用已授权收款人、原始输入和账户上下文生成结构化草稿；必须增加 schema 校验并接入现有澄清、验证和风控。模型不能获得签名密钥或执行权限。真实模型语义解析、独立验证模型、真实 KYC、WebAuthn / 生物认证、银行 API、持久账本与外部审计存证都未实现。
